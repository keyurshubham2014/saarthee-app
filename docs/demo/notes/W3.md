## Assumptions
- ASSUMPTION: Admin HTTP goes through the core `dioProvider` (standard headers) via a feature-local `AdminApi` wrapper that attaches `Authorization: Bearer` per call and maps failures to a typed `AdminApiError`. Any 401 on an authenticated admin call (not only TOKEN_EXPIRED/REVOKED) ends the session, since the server is authoritative. The core dio is never mutated (no shared interceptor), so citizen calls never carry the admin token.
- ASSUMPTION: Session-end navigation is driven by `AdminSessionGuard` (wraps the shell and every admin detail screen) listening to `adminAuthProvider`, because the app router's `refreshListenable` belongs to W2. Expiry is also checked on app resume and in each route redirect (TASK-05 §5.6).
- ASSUMPTION: Due badge count = items in the first `due=true` page with `limit=200` (TASK-06 §5.6). The badge is hidden on error.
- ASSUMPTION: WhatsApp click-to-chat is `https://wa.me/<digits>?text=<urlencoded>` (TASK-06 §5.6). If the reminder response has no phone (`phoneE164: null` is possible in the W1 implementation), the sheet hides the recipient line and opens `https://wa.me/?text=…` so the operator picks the chat.
- ASSUMPTION: H1/H2 arrive as ratios (0..1) and are shown with `NumberFormat.percentPattern` (0–1 decimals). Small-sample note per row when `verified < 10`.
- ASSUMPTION: The Rates "Trusted sources" card is the row with `group == 'trusted'`; other rows keep server order.
- ASSUMPTION: The All-tab Category filter reads `GET /admin/categories` (TASK-09); until that endpoint exists the Category chip shows a load error in its sheet path and the other filters still work.
- ASSUMPTION (deviation): there is no share-sheet package in `pubspec.yaml` (W3 may not edit it). So the invite-code "Share" button copies the ready-made message ("Install the app and enter code {CODE}") to the clipboard, and Export saves the CSV to the downloads folder (`getDownloadsDirectory()`, falling back to app documents) and shows the saved path instead of opening the OS share sheet. Adding `share_plus` later changes only these two call sites.
- ASSUMPTION: Category reorder sends one PATCH `sortOrder` per moved category, renumbered in steps of 10 (TASK-09 §5.6). The list stays disabled while saving and reloads from the server afterwards, so a failure restores the server order.
- ASSUMPTION: Status chip wording: `reminded` → "Waiting" (02 §2.1 "⏳ Waiting"), `filed` → "Filed".
- ASSUMPTION: Strings that only an admin sees (filter values, fact labels, confirm texts) were written in the spec's plain-English tone where the spec gives no copy.
