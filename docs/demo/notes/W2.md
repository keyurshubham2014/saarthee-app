## Design decisions
- Verify token transport: Flutter's built-in deep linking is disabled (`flutter_deeplinking_enabled=false` on Android, `FlutterDeepLinkingEnabled=false` on iOS). `app_links` receives `saarthee://verify?t=…`, `parseVerifyInput` extracts the token into the memory-only `verifyTokenProvider`, and the router goes to `/verify` with NO token in its location. The token is sent only in `X-Verify-Token` (VerifyRepository), never logged, persisted or put in an event. Unparseable link → `/verify/enter-code` + `deep_link_failed {reason: unparseable}`; manual entry → `deep_link_failed {reason: manual_entry}`.
- Draft persistence: `reportDraftProvider` writes JSON to shared_preferences on every change, including the current step (`step`); the compressed photo is moved into `<appDocs>/drafts/`. Step 2 saves the step before launching CCRS/WhatsApp/dialer. On cold start the router's initial location is the draft's saved step, so the app reopens on step 2 after the OS kills it. Drafts are deleted only after 201/200. Errors never clear drafts.
- `ErrorSummary` is named `AppErrorSummary` in code: Flutter's foundation library already exports `ErrorSummary`, so the spec name causes an ambiguous import with `material.dart`.
- Verify step numbering: answer 1, photo 2, note 3 (not fixed only), check = last; total 4 when "not fixed", else 3 (TASK-07 §5.6).

## ASSUMPTIONS
- ASSUMPTION: On-device compression uses image_picker's built-in `maxWidth/maxHeight 1600` + `imageQuality 80` instead of adding flutter_image_compress (avoids a new dependency; same 02 §8.2 targets). The picker's cache file is copied into the draft folder and deleted.
- ASSUMPTION: Fonts: no font files bundled (Anek licence/coverage check not possible offline within the time box); the theme uses the platform default (Roboto / SF). The type scale, weights and sizes follow 02 §2.1. Bundling Noto Sans (+Gujarati/Devanagari) is a follow-up.
- ASSUMPTION: Reduce motion: step transitions are a 220 ms fade via `stepPage`, skipped when `MediaQuery.disableAnimations` is set.
- ASSUMPTION: Portrait lock is applied per route with `SystemChrome.setPreferredOrientations` from a router listener (`/admin*` rotates, everything else portrait).
- ASSUMPTION: Global error handler: in release builds an uncaught error routes to `/error` ("Something went wrong" + "Go home"); in debug builds errors are only logged (type only, no payload). Storage is never touched.
- ASSUMPTION: The invite code from settings is sent with every report as `inviteCode`. "I don't have a code" clears any stored code.
- ASSUMPTION: Backing out of step 1 before choosing a category discards the empty draft, so Home does not offer "Continue your report" for a draft with no answers.
- ASSUMPTION: Upload starts automatically after "Use this photo" and is retried when connectivity returns while the photo step is open.
- ASSUMPTION: `PHOTO_UNUSABLE` at submit clears the draft photo (report) / session photo (verify) and the error summary links to the photo step to retake.
- ASSUMPTION: CCRS WhatsApp opens `https://wa.me/<digits of CCRS_WHATSAPP_NUMBER>`; defaults for `CCRS_WEB_URL`, `CCRS_WHATSAPP_NUMBER`, `AMC_HELPLINE` are the 05 §2.2 values and can be overridden with dart-defines.
- ASSUMPTION: Verify photos are uploaded without a `purpose` field (the verify endpoint derives the purpose and complaint from the token).
